# 🚀 Doc-Forge: Декларативный компилятор и инспектор академических документов по ГОСТу

Doc-Forge — это локальный программный комплекс для **двусторонней работы с академической документацией** (курсовые, дипломные проекты, отчеты по практике, рефераты). 

Комплекс решает фундаментальную проблему верстки: **полное разделение семантического текста (Markdown от AI) и правил типографики (декларативные YAML-профили ГОСТ/СТО)**.

---

## 🎯 Ключевые возможности

1. **Реверс-инжиниринг образцов (`inspect`):**
   * Анализирует присланный файл `.docx` (методичку или эталонный диплом от преподавателя).
   * Автоматически извлекает точные размеры полей (мм), параметры основного шрифта, красной строки (см), межстрочных интервалов и отступов заголовков (pt).
   * Сохраняет готовый к правкам YAML-профиль.

2. **Декларативные профили оформления (`profiles/*.yaml`):**
   * Все правила верстки хранятся в открытых текстовых файлах.
   * Ты и AI-агент можете в диалоге менять любые параметры (например, изменить кегль таблиц на 11pt или убрать абзацный отступ у H2), и правки сразу применяются.

3. **Аппаратная защита от типичных ошибок LLM:**
   * 🛡️ **Никаких паразитных пустых строк:** Двойные переносы строк (`\n\n`) никогда не превращаются в пустые параграфы Word.
   * 🛡️ **Защита от висячих заголовков:** Ко всем заголовкам автоматически применяется флаг `<w:keepNext/>`.
   * 🛡️ **Идеальный титульный лист:** Генерируется на базе изолированного раздела Section 1 без колонтитулов и со строгой координатной сеткой подписей.
   * 🛡️ **Нативное оглавление:** Собирается с точками-отточиями (leader dots) по правому краю поля страницы.

4. **Генерация 4-страничного тестового документа (`test`):**
   * Мгновенно собирает эталонную 4-страничную работу для визуальной проверки верстки.

## 📁 Структура проекта

```
doc-forge/
├── flake.nix             # Nix Flake с окружением Python, LibreOffice и poppler
├── shell.nix             # Поддержка nix-shell
├── README.md
├── profiles/             # Декларативные профили нормоконтроля
│   ├── samek.yaml        # ГБПОУ Самарский металлургический колледж (СаМеК)
│   ├── samgtu.yaml       # СамГТУ (СамГТУ ИАИТ)
│   └── gost_7_32.yaml    # Эталонный ГОСТ 7.32-2017
├── test_samples/
│   └── sample_4page.md   # Образцовый 4-страничный Markdown
├── output/               # Скомпилированные .docx и .pdf
└── src/
    ├── schema.py         # Pydantic-модели валидации профилей
    ├── title_engine.py   # Движок генерации титульных листов
    ├── toc_engine.py     # Движок генерации оглавления
    ├── compiler.py       # Компилятор Markdown -> DOCX
    ├── inspector.py      # DOCX -> YAML инспектор образцов
    └── cli.py            # CLI интерфейс (Typer + Rich)
```

## 🛠️ Использование CLI

### Запуск окружения в NixOS:
```bash
cd /home/detker/Документы/repository/doc-forge
nix-shell
```

### 1. Генерация 4-страничного тестового документа:
```bash
python3 src/cli.py test samek
```
*Результат:* Создает `output/test_4page_samek.docx` (Стр. 1: Титульник, Стр. 2: Содержание, Стр. 3: Глава 1.1, Стр. 4: Глава 1.2 + Таблица + Список + Источники).

### 2. Сборка реальной курсовой или диплома из Markdown:
```bash
python3 src/cli.py build work.md -p samek -o output/diploma.docx
```

### 3. Анализ присланной методички / образца преподавателя:
```bash
python3 src/cli.py inspect /path/to/metodichka_sample.docx --name pgu_ti
```

### 4. Просмотр списка профилей:
```bash
python3 src/cli.py list
```

### 5. Детальный просмотр параметров профиля:
```bash
python3 src/cli.py show samek
```

## 🤖 Совместная работа с AI-Агентом (Hybrid Workflow)

Если преподаватель просит изменить формат:
1. Ты пишешь агенту: *"Препод просит сделать отступ перед H1 равным 18pt, а шрифт таблиц 10pt"*.
2. Агент открывает `profiles/samek.yaml`, точечно правит строки `spacing_before_pt: 18.0` и `font_size_pt: 10.0`.
3. Агент запускает `python3 src/cli.py test samek` и подтверждает корректность сборки.
